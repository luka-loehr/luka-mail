## Summary

`isolateMtaStsHosts` ran before `securityHeaders`, returned headerless responses, and called `next()` whenever an `mta-sts.*` hostname was not in static `MANAGED_DOMAINS_JSON` (exposing the full `/v1/*` and `/auth/*` surface on dynamically added or misrouted `mta-sts.*` hosts); meanwhile `/auth/native/start` used `script-src 'unsafe-inline'` instead of a per-request CSP nonce and responses lacked default `Cache-Control: no-store`.

## Evidence

- `src/worker/index.ts` and `src/worker/mta-sts.ts`: `app.use("*", isolateMtaStsHosts)` preceded `securityHeaders` and fell through to `next()` when `managedDomains(env)` did not list the domain.
- `src/worker/auth.ts` and `src/worker/native-auth.ts`: `HTML_CSP` allowed `'unsafe-inline'` scripts rather than `'nonce-...'`, overwrote route-specific `Content-Security-Policy` headers, and left `Cache-Control` unset on JSON/HTML responses.

## Risk

Unintended API exposure on `mta-sts.*` DNS records, missing `HSTS`/`nosniff`/`X-Frame-Options` on MTA-STS responses, weaker XSS defense-in-depth on passkey HTML pages, and proxy/browser caching of authenticated API responses.

## Fix and current state

Fixed in `26f4d72` (`src/worker/index.ts`, `src/worker/mta-sts.ts`, `src/worker/auth.ts`, `src/worker/native-auth.ts`, `src/worker/passkeys.ts`): moved `securityHeaders` first in the middleware stack, made `isolateMtaStsHosts` fail closed with 404 on every `mta-sts.*` hostname (serving `/.well-known/mta-sts.txt` for static `MANAGED_DOMAINS_JSON` and D1 `managed_domains`), generated a 16-byte cryptographic CSP nonce per request (`script-src 'nonce-...'`), preserved route-specific CSP headers, and defaulted `Cache-Control` to `no-store`.

## How to verify

- `npm test -- tests/security-hardening-v2.test.ts tests/edge-surface.test.ts tests/native-auth.test.ts`: confirms unmanaged `mta-sts.*` hosts return 404 with full security headers, `/auth/native/start` emits matching `script-src 'nonce-...'` and `<script nonce="...">`, and `/sender-logo` retains `sandbox` CSP.
